# opto-sync architecture and hardening audit — 2026-07-25

Scope: `syncer.c`, `opto-sync-clients`, and `opto-sync-e2e`.

## Executive assessment

opto-sync is now a deterministic JSON reconciliation engine, a versioned
reference synchronization protocol, and a set of durable client queues. The
product boundary is:

1. **syncer.c** decides how two JSON values reconcile.
2. **language/ORM/SQL adapters** invoke that decision atomically where possible.
3. **clients** keep authoritative server state separate from durable pending
   mutations and render a rebased local view.
4. The versioned **wire/server protocol** orders pull changes, deduplicates
   pushes, represents deletes/rejections, and resets replicas behind retention.

All four layers now have reference implementations. The reference server
verifies asymmetric Supabase-compatible JWTs (or exact static test mappings)
and binds identities to subjects, tenants, and clients; production applications
still own integration with their real identity provider,
application-specific record authorization, external-write change capture,
retention operations, observability, and backend-specific scaling.

| P1 | Client SDKs had durable protocol primitives but no shipped coordinator, leaving every adopter to rediscover pull-before-push ordering, reset recovery, safe retry, and persistence ordering. | Added transport-neutral TypeScript/Dart `ProtocolSyncLoop` coordinators and Rust `ProtocolSyncDriver`, bounded paging/batching, full-jitter retry helpers, runtime response validation, durable wake hooks, explicit Rust persistence rollback, and live PostgreSQL tests in all three languages. |
| P0 | SDK acknowledgement APIs accepted a server watermark without proving it covered only the immutable batch actually sent, so a malformed response could discard unsent queued work. | TypeScript, Dart, Rust, and Gleam now require the original `PushRequest`, compare it to the current durable pending prefix inside the relevant local transaction/state transition, and validate matching client/protocol, exact terminal watermark, ordered one-result-per-mutation coverage, duplicate provenance, and canonical checkpoint/revision values before confirming anything. |
| P1 | IndexedDB/SQLite applications could write an optimistic row and queue intent as two independent commits, violating the local-first invariant under a crash or exception between them. | TypeScript and Dart expose `queueMutationAtomic` / `queueDeleteAtomic`, running the application callback, sequence allocation, and queue insert in one Dexie/Drift transaction. | P1 | Coordinators applied downloaded rows and persisted the pull checkpoint as separate operations even when both shared one database, unnecessarily requiring idempotent replay after a crash. | TypeScript and Dart now provide atomic pull-page/snapshot helpers plus verified atomic coordinator callbacks; Rust adds `AtomicProtocolSyncStore` and `sync_cycle_atomic`. | P1 | Dart's native client imported `dart:ffi` unconditionally and had no durable browser path, so Flutter web could not satisfy the SQLite-or-IndexedDB platform contract. | Added conditional native/stub imports, a typed WASM syncer, and Drift SQLite persisted explicitly through IndexedDB. | P1 | Gleam had neither a dedicated binding nor a protocol client, and the first opaque queue draft could not be durably restored. | Added a typed Gleam wrapper over the real BEAM NIF and a transport-neutral protocol v1 client with strict wire decoding, bounded queueing, a versioned snapshot codec that preserves payload bytes, and live PostgreSQL push/retry/pull/delete coverage. |

## Canonical reconciliation contract

| Option | Default |
|---|---|
| array strategy | `MERGE_BY_KEY` |
| identity selectors | `id` |
| timestamp resolution | enabled |
| LWW selectors | `updatedAt,syncedAt` |
| FWW selectors | unset |

Timestamp selectors are either direct keys or JSON Pointers relative to the
current merge node:

```text
updatedAt
#/_sync/updatedAt
#/metadata/server~1timestamp
```

The last selector reads `metadata["server/timestamp"]`; `~1` and `~0` follow
RFC 6901. This supports nested metadata in JSONB, SQLite JSON text, IndexedDB
objects, and in-memory records without teaching the C core a schema.

## Database deployment matrix

| Target | Recommended interface | Notes |
|---|---|---|
| PostgreSQL you operate | PGXS extension + `opto_sync_merge`; optional `BEFORE UPDATE` trigger | Atomic in the database and independent of application ORM. |
| Self-hosted Supabase | Include the PostgreSQL extension in the database image | Apply RLS/authorization before invoking reconciliation. |
| Hosted Supabase | WASM in an Edge Function or application/server binding | Hosted projects cannot load an arbitrary native shared object; supported/pure-SQL extensions are platform-controlled. |
| Native SQLite | Loadable extension + atomic UPSERT | `SET data = opto_sync_merge(data, excluded.data)` avoids a read/write race. |
| Browser IndexedDB | TypeScript + Dexie/WASM, or Dart + Drift SQLite/WASM | Both paths fail closed rather than accepting an in-memory fallback; render/rebase pending work over authoritative state. |
| Dart/Flutter SQLite | Drift adapter, or SQLite extension where loading native extensions is available | Drift helper uses one transaction and bound values. |

## ORM coverage and target

The SQL function is the universal escape hatch: any ORM that can issue a raw
function call can reconcile atomically without a bespoke lifecycle hook.
Dedicated adapters still improve ergonomics, type safety, and concurrency.

| Ecosystem | Implemented | Next supported set (priority order) |
|---|---|---|
| TypeScript/JavaScript | Drizzle, Kysely, TypeORM, Prisma | Keep these four; add Sequelize only if demand justifies its hook complexity. |
| Rust | Diesel, SQLx, SeaORM | Turn the three pure helpers into transaction-aware database helpers before adding a fourth ORM. |
| Go | GORM, Ent, Bun | Keep a small `database/sql` helper as future work for sqlc/SQLBoiler users. |
| Dart | Drift, Floor, Isar | Keep SQL and object-store transaction requirements explicit; consider ObjectBox only on demand. |
| BEAM | Ecto, Ash | Ash uses its public changeset surface; both still require a data-layer transaction/lock for stale-resource protection. |
| C / SQL | SQLite, PostgreSQL | Add a length-aware C API first; then consider MySQL/MariaDB UDFs and DuckDB based on deployment demand. |

“Two to five per language” is a useful coverage goal where an ecosystem has
several dominant ORMs. It should not override quality: a database adapter must
either perform one atomic SQL expression, hold a row lock through read/write,
or use a tested compare-and-swap retry. An adapter that merely wraps a pure
merge and implies concurrency safety is worse than no adapter.

## Comparison with Linear and open-source sync engines

Linear validates the local-first direction: its UI applies mutations
immediately, persists pending transactions in IndexedDB, sends them
asynchronously, and reconciles server changes into an in-memory model. opto-sync
now has the analogous durable queue, rebase primitive, and a tested reference
push/pull protocol. Its TypeScript and Dart clients can now atomically commit a
same-database optimistic row with the queue intent, but it still does not own
Linear's integrated model graph, production
authorization, or operational scale
([technical breakdown](https://performance.dev/how-is-linear-so-fast-a-technical-breakdown),
[Tuomas Artman interview](https://www.localfirst.fm/15/transcript)).

The source-level comparison points to the next protocol work:

| Project | Mechanism worth copying |
|---|---|
| Replicache | Apply authoritative patch, then replay pending mutators during rebase. |
| Electric | Preserve transaction groups and distinguish accept/reject/retry. |
| RxDB | Persist directional checkpoints, compare against assumed master state, and use live events as resync hints. |
| PowerSync | Separate downloaded bucket state from durable CRUD upload transactions. |

Detailed code links and tradeoffs live in
[`opto-sync-clients/docs/SYNC_PATTERNS.md`](../../opto-sync-clients/docs/SYNC_PATTERNS.md).

## Remaining production work

1. Add application-specific per-record ACLs or PostgreSQL RLS. The reference
   service now locally verifies asymmetric Supabase-compatible JWTs through
   HTTPS JWKS, validates issuer/audience/lifetime/role and signed tenant/client
   claims, preserves durable client ownership across token refresh, and has
   full adversarial unit plus live PostgreSQL coverage.
2. Attach `syncer_protocol_capture_change()` to every authoritative
   application table, or replace it with logical decoding/WAL or a mandated
   write service. Migration 2 now supports arbitrary tenant/id/JSON column
   names and whole-row capture in the same commit-ordered stream; deployments
   must review whole-row secret exposure, apply mirror/log grants and RLS, add
   per-record authorization, and avoid irrelevant-update churn with narrowly
   scoped triggers where needed.
3. Extend the existing transactional compaction and push failpoints to every
   remaining SQL statement, then run actual process-kill crash tests. The
   committed-but-response-lost window is now verified end to end; production
   compaction already uses the state lock and a separate admin credential, and
   deletion plus pre-commit rollback are verified.
4. Add deployment-wide distributed rate limiting and run the provided recovery
   drill against production-sized data to establish deployment-specific RPO/RTO
   and off-site retention. The reference now has checksummed transactional
   migrations, a migration-only command, a full logical backup/restore gate,
   traffic/snapshot quotas, protected metrics, structured audit events, a
   process-local limiter, and correctness-gated load/latency CI; the
   protocol-aware TypeScript, Dart, Rust, and Gleam queues have configurable
   pending-count and payload-byte limits plus confirmed-history pruning.
5. Add a first-party durable Gleam/BEAM adapter only where its database can
   guarantee the optimistic row and queue snapshot commit in one transaction.
   Rust now has a first-party SQLite store with injected rollback,
   close/reopen, queue-corruption, acknowledgement-overlay, snapshot,
   checkpoint, quota, and multi-connection contention tests plus a live
   PostgreSQL commit/crash/retry/reopen path. Pluggable contracts alone still
   are not evidence that every downstream adapter is crash-safe.
6. Replace the singleton checkpoint lock if throughput requires it, using a
   WAL/LSN-derived or partitioned design that preserves observable commit order.

Until those application and operational controls exist, describe opto-sync as
a hardened reconciliation engine plus reference sync protocol—not a turnkey
replacement for Linear, Electric, PowerSync, Replicache/Zero, RxDB, or
WatermelonDB.
